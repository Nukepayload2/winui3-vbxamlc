# 上游合并账本（upstream-merge）

本 fork（winui3-vbxamlc）跟踪 microsoft-ui-xaml 上游。VB 生成器散布在上游共享代码（`src/XamlCompiler/`），上游会持续改动 C#/原生生成器与编译器管线，而 VB 生成器依赖同一模型层——所以本 fork 的合并策略与「新增为主」的纯扩展 fork 不同：**VB 改动尽量新增，但生成器改动与 C# 同步是常态**。

## 原则

- 本地 VB 改动「新增为主、尽量不侵入既有 C#/原生路径」——降低合并冲突面。
- 修改面外文件直接跟随上游；修改面内文件（VB 生成器、`Language.cs`、模型层 `VBName()`）逐个 3-way 评审合并。
- 上游改动生成器 / C# 基线时，检查对应 VB 生成器是否需要同步（见 `xaml-compiler-index.md`「维护纪律」）。
- 合并后跑全量测试 gate（单元 + 回归 + VB 端到端）。

## 操作

（随首次合并落地：记录上游版本、合并点、冲突、验证结果。）

- 首次合并前先确认：上游当前基线、本 fork 差异面清单、VB 生成器相对上游的改动量。
- 每次合并记录：`上游 commit` → 合入日期 → 冲突文件 → 解决方案 → 验证结果。
